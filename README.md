## 目前版本

### 本地資料與更新

正式資料保存在 `local_db/`：`history_prices.sqlite3`、`history_reference.sqlite3` 保存既有歷史快照，`official.sqlite3` 保存證交所、櫃買中心及公開資訊觀測站的新增行情、財報與公司行動。三個檔案需一起備份；正式流程不再登入 FinLab 下載資料。

每個交易日21:00更新行情並檢查財報及除權息公告；最後交易日前一個交易日晚間同時計算下次調倉資料，21:45只補做未完成發布，調倉日06:00複核、07:00補救。財報依季度與公司適用生效日使用，後來取得的修訂只從觀察日起生效，不改寫已公布歷史。資料不完整時停止發布並保留上一份計畫。

採原 A 選股規則為唯一選股池，取消 B 通道、台積電開關及 60/40 預算。以三日平均 RSI20 排名，最多15檔；合資格續抱股前20名可保留，新股由前15名補入。保留100%個股權重偏離門檻、90～95%配置修補、整股、費用及公司行動規則。

2015-01-05～2026-10-16、初始10萬元複利：純 V5 歷史回測年化47.01%、每日最大回撤31.40%。這是同一段歷史比較後選出的方案，不保證未來優於 V4。完整每日資產與成交已核對原純A研究結果一致。**注意：這段歷史同時用來挑選方案，屬於「事後選出的最好成績」，實際操作的報酬很可能明顯較低、回撤也可能更大。**

配置參考完整使用2015年起的純V5模型，保留原始買入係數1.5／1／0.5；本週模擬成交帳戶接續上週V4實際發布的帳本，據此計算買賣差額。`live_model_seed.json` 保留2026-10-16現金、股數、應收股利、待領股票及前期訊號摘要；`v5_engine/live_model.py` 負責還原。2015年起的績效圖為純V5歷史回測，與這個接續帳本分開。網頁仍輸入上週與本週總資金，保留已儲存理論股數。

各版本改動見 [VERSION_HISTORY.txt](VERSION_HISTORY.txt)；V4 及更早的說明移到 [舊版 README 紀錄](research_notes/readme_archive_v4.md)。

## 本機

Python 3.12：`pip install -r requirements.txt`。

正式更新使用本地 SQLite 資料庫與官方免費來源，不再需要 FinLab 認證。FinLab Python 套件僅保留已驗證的資料格式與持股訊號運算。Telegram 使用 `TG_TOKEN` 和 `TG_CHAT_ID`。

`local_db/history_prices.sqlite3` 與 `history_reference.sqlite3` 保存不可變歷史快照；`official.sqlite3` 保存新行情、財報、公告原文、來源雜湊及更新紀錄。資料先完整驗證再一併提交，任一必要來源失敗則保留上一份；資料庫隨版本保存，可由 Git 還原。`python sync_market.py` 是唯一正式資料更新入口，`update_data.py` 只讀取結果產生網頁。

`python preflight.py` 執行離線檢查，不發送訊息或改寫模擬持倉。

## 自動化

GitHub Actions 每個交易日21:00更新官方本地資料庫；最後交易日前一交易日同時產生並發布本週計畫；正常週為週四晚間，以週四資料供週五收盤調倉。21:45僅補做尚未完成的發布，已完成則略過。排程可能延後啟動，資料及網站驗證完成後才通知。夜間排程逐一檢查平日，僅正確訊號日啟動，因此週五休市時自動提前至週三晚間產生週四計畫。候選結果通過暫存發布檢查才更新正式資料，並明確要求 Pages 重建。

最後交易日06:00先複核前晚訊號、網站及TG，全部完成不重算股數、不重發；缺資料才補算，僅發布或通知失敗就補該步驟。07:00保留第二次補救。其他平日06:00仍更新日常行情。排程均使用 GitHub Actions，平台延遲及上游資料未齊時不能保證準點完成。

`publication_check.py` 在 Pages 建置完成後讀回公開網址，核對 HTML 完整 SHA-256、內嵌訊號指紋、版本、基準日、調倉日與驗證狀態。公開網站不一致則停止一般調倉推播，Telegram 發送前再核對一次。

`Python pipeline checks` 於 PR 與正式版程式更新時執行語法檢查和離線測試。

## 每週狀態與重試

頁首狀態依台北當日及休市表計算，每分鐘重新確認；完成狀態必須同時符合本週調倉日、前日資料基準及驗證通過。舊清單會明確標成最近一期模擬資料。

價格更新、訊號產生、網頁重建及 Pages 建置失敗時，最多執行三次：第一次失敗後等 60 秒，第二次後等 180 秒。每次仍須通過原本資料驗證。Telegram 傳送不整段重試，避免部分成功後重複發送。

`delivery_state.py` 在每段 TG 送出前保存發送意圖，Telegram 回覆成功後保存訊息編號；Actions 中每次寫入立即提交回 GitHub。補跑只處理未送出的分段，已確認分段略過，手動 full 也不重發整份相同訊號。若傳送逾時、執行器中斷，無法確定是否送達的分段會停止自動重發並讓流程告警；需對照實際 TG 確認，不能宣稱網路傳送可保證恰好一次。

最終失敗時，流程嘗試將失敗狀態發布到網站，保留已有訊號，再發告警。若 GitHub 或網站本身故障，失敗狀態也可能無法上網；頁面仍會依日期判斷舊清單，不能把上一週資料顯示為本週已完成。

## 引擎與資金試算

`v5_canonical.py` 是指令入口，計算在 `v5_engine/`：

- `config.py` / `context.py`：參數與資料容器。
- `market.py` / `selection.py`：資料與候選名單。
- `execution.py` / `simulation.py`：先賣後買、整股與現金、配置區間。
- `performance.py`：全部成交的盈虧、以去年年底為基準的年度報酬。
- `canonical.py` / `validation.py` / `pipeline.py`：Web/TG 輸出、驗證、發布。
- `allocation.py` / `capital_preview.js`：目標整股配置與模型費用試算，Python/JavaScript 有一致性檢查。

研究入口 `v5_backtest.py` 使用相同引擎，輸出到 `research_output/`（可用 `--output-dir` 指定）；保留 `daily_trade_plan.csv`、`_final_candidate_report.txt` 與績效 JSON，沒有獨立的第二套成交或績效邏輯。

`python v5_canonical.py --report-only --capital 200000` 可模擬不同起始本金的完成期間績效；使用 `V5_OUTPUT_DIR` 將研究結果放在獨立目錄。非預設本金只能產生報表，不能替換共用週訊號。

網頁輸入的是目前用於目標配置的總資金。目標股數、預估現金與費用依實際整股試算；高價股票不足一股或目標權重本身不足時會明列提醒，不保證任何本金都能達到 90–95%。模型費率由參數提供，實際券商費用與成交另計。

「查看配置差額」逐檔列出重分配後目標金額、試算股數、投入與少投入金額，區分不足一股、取整、缺報價及資金含費用限制；同時顯示距離90%下緣的金額。重分配及整股修補後仍未用完的額度保留現金，不新增選股名單以外的股票。

盈虧比以已完成週期的實際模擬獲利金額／虧損金額计算；沒有已完成虧損時，JSON 使用 `null`，不填造假的 `999`。年度報酬包含跨年的第一週，並可與整段資產成長核對。

### 兩週總資金試算（V4.5.0）

上週、本週總資金均手動輸入（持股市值＋現金）。按「計算本週買賣」查看差額；續抱優先不動，必要時調整整體90～95%倉位。上週已儲存理論股數優先，首次依上週模型推估。詳細規則見 research_notes/v4_5_0_two_capitals.md。回測績效及TG仍為原策略模型，不代表個人兩週資金試算績效。

## V4.6.0 統一防買回調倉

正式回測與瀏覽器共用 `weekly_capital.js`。Python 需同時安裝 Node.js 22；缺少執行環境時停止發布。V4 原路徑僅提供逐期選股及參考權重，實際帳戶由獨立現金／持股帳本與防買回規則計算；兩者資金和股數不混用。`planner_target_weight` 保存參考配置，`target_weight` 保存實際調整後配置。回測保留漲停不買、跌停不賣、停牌及配股未入帳限制。網頁個人追加／提領資金不計入年化；歷史績效不是個人實盤紀錄。
